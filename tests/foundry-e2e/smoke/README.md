# Smoke-сценарий: живой бой с AI-ботами

Ручной acceptance-прогон `only-war-ai` в реальном мультиплеере:
1 GM + 3 игрока против 10 ботов в трёх группах с разными тактиками.

## Подготовка

```powershell
# Foundry с миром only-war-test, система only-war-local, модуль only-war-ai
cd tests/foundry-e2e
node smoke/setup-smoke.mjs      # пользователи, актёры, арена, staged combat
node smoke/open-players.mjs     # 3 вкладки игроков рядом с GM
# после прогона:
node smoke/close-players.mjs    # закрыть вкладки игроков
```

`setup-smoke.mjs` создаёт:

| Сущность | Что |
|---|---|
| Пользователи | Smoke Player 1–3 (роль Player) |
| Персонажи | Acolyte One–Three (OWNER у своего игрока), lasgun |
| Команда `alpha-smoke` | 4 Alpha Trooper — пресет `assault`, гибриды (lasgun + chainsword), cohesion 5, характер `shock`, лидер с чертой `fanatic` |
| Команда `beta-smoke` | 3 Beta Rifleman — пресет `rangedCover`, cohesion 6, характер `disciplined`, один `cowardly` |
| Пара `spec-smoke` | 2 Spec Operative — пресет `specOps`, cohesion 4, характер `elite`, лидер с `flanker` |
| Одиночка | Hold Gunner — пресет `hold` в здании, черта `sentinel` |
| Сцена | Smoke Arena 40×30 клеток: открытое поле, здание с дверью в центре, укрытия, южный фланговый коридор |
| Бой | Smoke Combat — staged, жмём «Begin Combat» |

Характер (`character`) пишется во флаг fireteam каждой команды, черты
(`personality`) — во флаг актёра. У ботов без явного флага личность
генерируется seeded из `actor.id` — она стабильна между прогонами.

Карту можно перерисовать руками — сценарий от неё не зависит, важны:
открытое поле, хотя бы одно закрытое помещение, укрытия, фланговый обход.

## Рекомендуемые настройки для прогона

- `only-war-ai.executionMode = "preview"` — ГМ видит план и подтверждает;
- `only-war-ai.diagnosticsEnabled = true` — в preview видна раскладка скора;
- `only-war-ai.masterEnabled = true`;
- `only-war-ai.previewTimeoutSeconds = 0` — без авто-отмены;
- `only-war-ai.aiDifficulty = "normal"` — базовый прогон; отдельные ходы
  повторить на `"easy"` (заметны промахи выбора) и `"hard"` (включается
  lookahead).

## Протокол

Отмечайте результат: ✅ / ❌ / ⚠️ (частично — с комментарием).

### A. Базовый цикл и разница тактик

| # | Проверка | Ожидается |
|---|---|---|
| A1 | Begin Combat → AI вычисляет контроллера | Один GM-контроллер, без диалога у игроков |
| A2 | Ход Alpha Trooper | Assault: сближение по открытому полю + атака (charge/выстрел) |
| A3 | Ход Beta Rifleman | RangedCover: занимает укрытие/держит дистанцию, стреляет из-за укрытия |
| A4 | Ход Hold Gunner | Hold: стоит на месте, стреляет только при видимой цели |
| A5 | Ход Spec Operative | SpecOps: отдельное поведение — обход/поддержка, не прямой штурм |
| A6 | Ходы игроков | AI не трогается, ждёт своего хода |
| A7 | Заметна разница между командами | Alpha идёт вперёд, Beta сидит за укрытием, Hold не двигается |

### B. Preview для ГМа

| # | Проверка | Ожидается |
|---|---|---|
| B1 | Наступает ход AI → preview-диалог у GM | NPC/пресет/цель/маршрут/шаги/ресурсы |
| B2 | Confirm | Ход выполняется: токен двигается по маршруту, атака кидается |
| B3 | Cancel | Ничего не происходит, ход остаётся под ручным управлением |
| B4 | Replan | Новый план с `replanCount`+1 |
| B5 | Вкладки игроков | Диалога нет вообще (ни тени окна, ни ошибок в консоли) |
| B6 | План показывает понятную причину (score breakdown) | ГМ понимает, почему бот выбрал действие |

### C. Тишина у игроков

| # | Проверка | Ожидается |
|---|---|---|
| C1 | Консоль вкладки игрока весь прогон | Нет AI-ошибок, нет предупреждений от модуля |
| C2 | Информ-сообщения AI | Игрок их не получает (только GM/controller) |
| C3 | Анимации/звуки бросков | Видят все как обычно — лишних UI-элементов нет |
| C4 | Любые `lacks permission` ошибки в Foundry-логе | Отсутствуют (боты пишут только через GM-контроллера) |

### D. Цели и вооружение

| # | Проверка | Ожидается |
|---|---|---|
| D1 | Несколько видимых целей | Бот выбирает осмысленно (ближайшая/самая уязвимая по score), не случайно |
| D2 | Гибрид (chainsword+lasgun), цель далеко | Выстрел из lasgun либо сближение |
| D3 | Гибрид, игрок подошёл в контакт | Бот предпочитает melee (chainsword), не стреляет в упор |
| D4 | Гибрид, игрок отошёл | Возвращается к lasgun/догоняет в melee по пресету |
| D5 | Два оружия ближнего боя у одного бота | Выбирает более сильное по score |
| D6 | Цель в полном укрытии/без LOS | Нет атаки; движение для получения LOS |
| D7 | Hidden-токен (скрытый) | Никогда не атакуется |
| D8 | Цель умерла до хода бота | Перевыбор цели, нет атаки по трупу |
| D9 | Кончились патроны в магазине | Переход на melee или hold, без ошибки броска |

### E. Группы и координация

| # | Проверка | Ожидается |
|---|---|---|
| E1 | Члены `alpha-smoke` | Общий TeamPlan, распределённые цели (не все в одну цель) |
| E2 | Spec-пара flank | Один держит/фиксирует, второй обходит — разные маршруты |
| E3 | Coordinated assault | Одновременный старт после barrier-проверки всех участников |
| E4 | Один бот команды невалиден (убит/скрыт) | Барьер не пускает частичный старт, команда держится/регруппируется |
| E5 | Мягкая cohesion | Члены не расползаются дальше preferredCohesion клеток |
| E6 | Удалённый (detached) член команды | Попытка regroup либо fallback-тактика |
| E7 | Конец TeamPlan | Временные assignments не сохраняются (нет мусора во флагах) |

### F. Статусы и гибель

| # | Проверка | Ожидается |
|---|---|---|
| F1 | Убить бота | Его ход пропускается; команда пересчитывает план (member lost) |
| F2 | Убить лидера команды | TeamPlan валидируется, происходит `leader-lost`/replan, команда не зависает |
| F3 | Статус `pinned` (подавлен) на боте | Бот не чарджит и не сближается (move-attack/approach, уменьшающие дистанцию, отклонены `pinned`); атака на месте и движение с сохранением/увеличением дистанции — легальны |
| F4 | Статус `prone` на боте | Бюджет движения уполовинен (ползком), чардж запрещён; обычное движение и атаки остаются |
| F5 | Статус на игроке | Бот учитывает его в оценке цели (pinned/prone/stunned — фактор `vulnerable`, лёгкий приоритет уязвимой цели) |

### G. Вмешательство и edge cases

| # | Проверка | Ожидается |
|---|---|---|
| G1 | GM вручную двигает бота после plan → до исполнения | `token-moved` → один replan, без дублирования действий |
| G2 | GM прячет цель после plan | Снапшот валидируется заново, нет атаки по невидимой цели |
| G3 | Игрок двигает свою цель-токен бота | Бот реагирует на новую позицию (last-known при потере LOS) |
| G4 | Цель зашла за угол (потеря LOS) | Last-known: бот идёт проверять позицию, НЕ стреляет «по памяти» |
| G5 | `masterEnabled = false` посреди боя | AI не заявляет и не исполняет ходы, preview не открывается, UI скрыт |
| G6 | Вернуть `masterEnabled = true` | AI возобновляет работу штатно |
| G7 | `executionMode = automatic` | Ходы выполняются без preview-диалога (для чистоты замера) |
| G8 | Второй GM зашёл в игру | Только один контроллер; дублирующих ходов/бросков нет |
| G9 | Бот зажат между союзниками (нет клетки) | `no-route`/partial → hold, без падения и без зависания |
| G10 | Все цели бота мертвы/скрыты | `no-target` → пропуск хода с end-turn, без ошибок |

### H. Длительная игра (опционально, 20+ ходов)

| # | Проверка | Ожидается |
|---|---|---|
| H1 | Нет накопления ошибок в консоли GM | Чисто |
| H2 | Нет «залипших» операций | Combat flag `operation` всегда завершается терминальным статусом |
| H3 | Время планирования хода | Субъективно: <2 с на бота; формально замерить `plan.diagnostics.ms` |
| H4 | Память last-known | Записи забываются через ~3 раунда без повторного обнаружения |

### T. Тактический уровень (issue #16)

| # | Проверка | Ожидается |
|---|---|---|
| T1 | Preview плана с движением | В разборе скора move-кандидата виден фактор `danger` (карта угроз) |
| T2 | `aiDifficulty = "hard"` | В `plan.diagnostics.lookahead` появляются `counterDamage`/`adjusted`; итоговый выбор может отличаться от базового argmax |
| T3 | `aiDifficulty = "easy"` | В `diagnostics.easyPick.mistake` периодически `true` — бот берёт не-top1 кандидат (неидеальные ходы) |
| T4 | Раненая цель в радиусе файртимы | `teamPlan.convergence` / общий `assignedTargetId` у способных членов — команда фокусирует добивание |
| T5 | Движение через открытое поле под огнём | Бот предпочитает маршрут/конечную клетку с меньшим `danger`, не идёт веером по открытому |
| T6 | Детерминизм | Один и тот же ход при неизменном мире → тот же `plan.id` (seed-повторяемость) |

### P. Личности ботов (issue #19)

| # | Проверка | Ожидается |
|---|---|---|
| P1 | Preview плана | В строке NPC видна личность (`fanatic`, `cowardly`, `flanker` и т.д.) и характер команды в скобках |
| P2 | Лист NPC (вкладка AI) | Поле черт (введённые id), read-only строка resolved-личности, селект характера в fireteam-секции |
| P3 | Явный флаг `personality` | Заданные в setup черты (`fanatic`, `cowardly`, `flanker`, `sentinel`) — именно они в `plan.personality.traits`, `source: "flag"` |
| P4 | Бот без флага | Черты сгенерированы (`source: "generated"`), 1–2 шт, идентичны при replan/новом бое |
| P5 | Характер команды | `plan.personality.character` совпадает с флагом команды (`shock`/`disciplined`/`elite`); заметен в поведении (shock лезет вперёд, disciplined держит строй) |
| P6 | `aiDifficulty = "easy"` | В сгенерированных личностях новых ботов чаще `cowardly`/`rookie`/`unsteady`/`reckless`; на `hard` — `veteran`/`marksman`/`flanker`/`cunning` |
